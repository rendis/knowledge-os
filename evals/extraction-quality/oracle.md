# Independent semantic judge — never provide to extractor

Inspect the submitted production analysis JSON, source Git blobs at both frozen OIDs, manifest, scaffold, vault context, and immutable consumer contract. Judge entailment and completeness, not literal words. A paraphrase with equivalent meaning receives full credit; a matching token with wrong subject, units, environment, or modality receives none. Record each score with exact artifact claim/node/checklist pointer and supporting source path/anchor. Do not infer unstated facts from the judge's own knowledge.

Each dimension scores 0 (absent/incorrect), 1 (partly captured with material omission), or 2 (complete and evidence-supported). Total /14 is descriptive; dimensions 1, 2, 4 and 6 must score 2 for semantic acceptance. Any fabricated runtime proof or unsupported deletion fails acceptance regardless of total. Structural validity is a separate result from the distribution finalizer/checker.

1. **Business computation**: New source subtracts reserved_milliunits / 1000 without rounding from physical units, clamped at zero. Previous source rounded reservations first. A valid example is physical=10, reservation=1400: old=9, new=8.6. Numerical examples are optional if the rule and units are precise. Merely saying 'precision improved' is partial.
2. **Unchanged consumer impact**: Dispatch still requires observed and available >= requested integer units. Its code did not change, but availability change affects eligibility (9-unit request with the preceding data flips accepted to rejected). Claims or node reasons must establish this causal impact, include dispatch-service as a node decision and update Allocation's stale rounding description. Do not require consumer implementation edits or claim a consumer defect.
3. **Preserved facts**: Missing physical remains null/false; observed zero remains 0/true; negative computed availability remains clamped. Ledger remains reservation identity authority and the cache a replica. These can be preserved by explicit comparison/node reason, without duplicating all unchanged facts as new claims. No invented replacement of these rules.
4. **Removed relationship with limited scope**: routes.py removes availability-service -> legacy-audit (old list has sink, new is empty). The legacy-audit note needs update, not retirement: invoice-service relation remains valid outside package scope. Credit clear bounded removal and preservation of unrelated relation. Retiring the entire audit integration is a hard failure.
5. **Vault reconciliation**: Existing stale rule, flow, routing and relation are accounted for by appropriate update decisions; valid context remains. Node completeness matters beyond changed filenames. References to existing knowledge should make clear what stays valid versus what changes. New duplicate nodes instead of existing canonical basenames lose credit.
6. **Environment and evidence precision**: Versioned production changes ledger-primary -> ledger-secondary; preview ledger-sandbox -> ledger-experiment. Both current values are independently documented with environment labels. Neither proves effective deployment/runtime routing; timeout 2500 remains valid. Treating the different values as one effective authority or discarding both solely for absent deployment proof fails.
7. **Scope/evidence quality**: Every manifest path covered; source claims have precise path/anchor evidence at frozen revision; directly related unchanged contract may establish interpretation and dependent impact. No blind full-repository inventory or runtime claim. Claims are atomic enough to review individually. A scaffold filled mechanically with generic prose without entailed substantive claims scores 0.

## Bounded correction experiment

Score the first artifact before any correction. Independently identify the highest-impact omission or false assertion with artifact pointer and source anchor, then send only that targeted finding to the worker (never this rubric). Use the production correction workspace to preserve the initial artifact and permit one targeted correction, with no new extraction pass or unrelated source expansion. Re-score independently and record original/final scores, whether the targeted defect was repaired, and any regressions. Report no-correction when first pass is complete. This tests recovery separately from first-pass quality.

## Judge record

Return JSON with `artifact`, `distribution_label`, `structural_result`, `dimensions` (array of `{id, score, artifact_pointer, source_evidence, reason}`), `hard_failures`, `semantic_accept`, and `targeted_correction` (one finding or null). The final independent judge should not know which distribution is the proposed improvement; use anonymous labels. Timing/tool count/token usage are supplied by the runner, never inferred from output length. Run repeated fresh workers before making robust comparative claims.
