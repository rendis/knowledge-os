# Associated investigation evidence

Use while mapping or refreshing a repository/change with associated investigations, or absorbing selected case knowledge. This supplies evidence to the existing documentation workflow, not another writer or a full-remap requirement.

Check source changes alone, changes clarified by a case, and relevant case evidence without a source change. At investigation closure, verified production deployment or a durable documentation gap, assess only the bounded knowledge delta through the responsible workflow. Automatic case absorption requires verified production applicability; source-only corrections retain their own evidence-policy route. Compare claim/evidence identity, revision or observation, current canonical destination and recorded disposition. Return verified destinations and limits to the case owner; no write or scheduling authority follows from discovering a gap.

When repeated drift or missed follow-up is likely, offer a scheduled refresh (`synchronize-ecosystem`); the user chooses cadence and authorized effects. A suggestion creates no schedule.

Decide contribution per claim, not from the case's overall status:

| Finding | Map/sync disposition |
| --- | --- |
| Repository or work-item match without a supported overlapping claim | Do not import the case; continue the independently supported source delta. |
| Unpublished case, future proposal, or claim without verified productive applicability | Keep case-derived knowledge pending for automatic absorption. A source-map observation independently verified from code may still follow its own evidence-policy route. |
| Published case with a relevant, productively applicable new or corrective claim | Map only the supported delta, including when no repository changed; use the ordinary independent review and return the verified destination to the case owner. |
| Same claim and evidence identity already represented at a verified canonical destination | Reuse the recorded disposition; do not re-extract or republish that claim. |
| Case spans several components or claims with different evidence states | Absorb each eligible part separately and leave the others pending; neither case closure nor one deployment settles the whole case. |

1. Use `<cli> links --vault "<VAULT_ROOT>" --node <stem>` and bounded public-case searches for repository remote, work-item or change identity. Inspect supplied case IDs directly. A repository match is only a lead: confirm overlap in component, revision and claim. An absent node link does not prove that no case exists.
2. Find relevant cases with `<CLI> investigation list --vault "<root>"` (the `--id` form returns the case path and its private directory, if any); preserve provenance and keep that directory supplementary.
3. Select useful reasons, agreements, restrictions/exceptions, supplied documents/correspondence, deployment/observation evidence and limits. Inspect their sources directly and match revision, environment, date and scope. An approval establishes an agreement, not execution. Case narrative is not proof of production behavior. Compare each selected register ID and evidence identity/revision or observation date with the case's Readiness disposition, recorded destinations and current canonical note. An already verified claim is covered, not a new candidate; a case-level `documented` outcome does not settle every claim. Revisit only a changed claim or newly supported limit, not the whole case.
4. Apply `evidence-sufficiency.md` and the cell profile claim by claim. Incorporate supported material not derivable from code, labeling its evidence type. Changed source follows normal delta mapping; external-only evidence can enrich an unchanged-source note through the existing external reconciliation path. Preserve source-analysis metadata unless the source was re-analyzed. For automatic investigation absorption during map/sync, require productive applicability separately from case publication, closure or source-branch selection; retain future-state proposals in the case. An independently supported source-map correction can still follow the explicit correction route under `evidence-policy.md` without treating the case as production proof.
5. Update canonical notes with the bounded delta and durable shareable provenance. Route lessons to their learning owner. Private correspondence requires permission before sharing. A destination must not depend solely on an ignored run, a case's private directory or a live case that may be retired.
6. Independently review complete resulting notes under `final-note-review.md` **before publishing them**. If the reviewer is unavailable or delegation is prohibited, leave the changes on their `sync/` branch unmerged and report the review blocker. A self-review receipt or structural check cannot substitute for that gate. Return only verified published destinations (or explicitly pending candidates), evidence boundaries and checks to the investigation owner; do not mutate, close or retire its case. No matching case is valid and does not block independently supported mapping.
